> Przeznaczona dla pilotów operacyjnych. Zastępuje papierowy chronometraż i ręczne logowanie rozchodów paliwa.

## 1. Kontekst i cel

Aplikacja ma zastąpić papierowy e-chronometraż używany przez pilotów podczas dnia lotnego. Rejestruje:
- czasy blokowe (off-block / on-block) dla każdego pilota
- czasy lotów (takeoff / landing)
- duty time (od meldowania do zakończenia służby)
- stany i rozchód paliwa
- liczniki startów i lądowań

Dane eksportowane są do Google Sheets jako arkusz dzienny — zastępując ręczne wypełnianie tabel.

---

## 2. Użytkownicy i środowisko

- **Użytkownik:** pilot (dowódca i/lub drugi pilot)
- **Urządzenie:** telefon Android (głównie), możliwy tablet
- **Środowisko użycia:**
  - w kokpicie podczas lotu → priorytet: szybkość, czytelność, duże elementy
  - na ziemi między lotami → priorytet: dokładność, szczegółowe formularze
  - częste silne nasłonecznienie → ciemny motyw (dark mode) jako domyślny
- **Łączność:** tryb offline-first; sync z Google Drive gdy dostępny internet

## 3. Wymagania funkcjonalne

### 3.1 Ekran powitalny / preflight briefing

Pilot wypełnia przed pierwszym lotem dnia:

| Pole | Typ | Wymagane |
|------|-----|----------|
| Kod pilota (np. MIW) | tekst | tak |
| Znak samolotu (np. SP-MIW) | tekst | tak |
| Lotnisko startu (ICAO) | tekst | tak |
| Lotnisko lądowania (ICAO) | tekst | tak |
| Czas meldowania (duty start) | time picker | tak |
| Rodzaj lotu | select: skoki / ferry / egzamin / lot techniczny / inne | tak |
| Oznaczenie klienta | tekst | nie |
| Poziom paliwa startowy (L) | liczba | tak |

### 3.2 Ekran roboczy — cockpit view

Główny ekran podczas dnia lotnego. Dwa stany:

**Stan: silnik wyłączony (ground)**
- duży przycisk START ENGINE z potwierdzeniem
- czas lokalny i UTC
- ostatni zarejestrowany lot (summary)
- skróty: tankowanie, zmiana załogi, lista ręczna

**Stan: silnik uruchomiony (running)**
- timer block time (od kliknięcia start)
- czas lokalny / UTC (live)
- prędkość GPS (GS, kt)
- wysokość GPS (ft)
- szacowany fuel on board (obliczany)
- licznik startów / lądowań (auto + ręczny)
- przycisk STOP ENGINE z potwierdzeniem

### 3.3 Algorytm auto-detekcji startu i lądowania

Detekcja na podstawie danych GPS:

**Start (takeoff):**
- GS > próg (sugerowane 45–55 kt) przez min. 3 sekundy
- LUB zmiana wysokości względem elewacji lotniska > próg (sugerowane 50 ft)
- zabezpieczenie: hystereza — po detekcji startu ignoruj kolejne przez 60 s

**Lądowanie (landing):**
- GS < próg (sugerowane 30 kt) przez min. 5 sekund
- ORAZ wysokość względem elewacji lotniska < 30 ft
- zabezpieczenie: nie zaliczaj lądowania podczas ciasnych zakrętów (chwilowy spadek GS) — wymaga spełnienia obu warunków jednocześnie

> ⚠️ Progi do kalibracji podczas testów z pilotami. Znane ryzyko: precyzja GPS consumer-grade może powodować fałszywe detekcje.

Opcja ręczna: pilot może dokliknąć start lub lądowanie.

### 3.4 Tankowanie

Formularz dostępny między lotami:

- stan paliwa przed tankowaniem (L) — podpowiada ostatnią wartość
- ilość dolana (L)
- stan po tankowaniu (wyliczany = przed + dolano)
- **kalkulacja zużycia:** średnie zużycie/h na podstawie czasu pracy silnika od ostatniego tankowania
- komunikat z wyliczonym zużyciem jako punkt kontrolny

### 3.5 Zmiana załogi

- zmiana dowódcy i/lub drugiego pilota
- rejestracja kodu pilota + czasu zmiany
- każdy pilot ma osobny licznik czasu blokowego

### 3.6 Zakończenie dnia lotnego

**Opcja "przerwa"** (nie kończy duty):
- zatrzymanie timera silnika
- możliwość wznowienia bez zakończenia dnia

**Opcja "zakończenie dnia":**
- stan końcowy paliwa (L)
- ewentualne uzupełnienie po ostatnim locie
- godzina zakończenia duty
- generacja statystyk dnia

### 3.7 Statystyki dnia

Po zatwierdzeniu zakończenia:

- czas blokowy per pilot (suma off-block → on-block)
- czasy lotów (takeoff → landing, per lot)
- duty time (czas meldowania → godzina zakończenia)
- liczba startów i lądowań
- paliwo startowe / dolane / końcowe / zużyte (obliczone)
- lista wszystkich lotów dnia z czasami

Dane edytowalne przed eksportem.

### 3.8 Ręczna lista wzlotów (fallback GPS)

Prosta tabela do ręcznego wpisu gdy GPS niedostępny:

| Kolumna | Opis |
|---------|------|
| Off block | czas (podpowiada zegar, edytowalny) |
| Takeoff | czas |
| Landing | czas |
| On block | czas |
| Uwagi | tekst |

Plus sekcja paliwa i stanów.

### 3.9 Eksport

- format: Google Sheets (arkusz dzienny)
- autoryzacja: Google OAuth 2.0
- struktura arkusza: do ustalenia (osobna specyfikacja)
- tryb offline: dane w kolejce, eksport gdy internet dostępny

## 4. Architektura UX — dwa tryby

Aplikacja automatycznie przełącza tryb na podstawie stanu silnika:

```
TRYB GROUND (silnik wyłączony)
├── pełne formularze
├── standardowe rozmiary elementów
├── dostęp do historii i edycji
└── akcje: tankowanie, zmiana załogi, zakończenie dnia

TRYB COCKPIT (silnik uruchomiony / w locie)
├── duże cyfry, maksymalna czytelność
├── minimum elementów na ekranie
├── tylko krytyczne akcje (stop, ręczny S/L)
└── parametry GPS live
```

**Motyw wizualny:** dark mode jako domyślny (kokpit, nasłonecznienie). Toggle na jasny dostępny w ustawieniach.

**Design language:**
- ciemne tło (#0d0d0d / #141414)
- zielony akcent na statusy aktywne (#2ecc71)
- amber na paliwo / ostrzeżenia (#f39c12)
- czerwony na stop / błędy (#e74c3c)
- monospacingowe cyfry na timerach i parametrach

## 6. Wymagania niefunkcjonalne i ryzyka

### Ryzyka techniczne

| Ryzyko | Poziom | Mitygacja |
|--------|--------|-----------|
| GPS w tle — Android battery saver zabija proces | 🔴 wysoki | Foreground Service z powiadomieniem w pasku; `expo-task-manager` |
| Fałszywe S/L detekcje (ciasne zakręty, słaby GPS) | 🔴 wysoki | Hystereza, podwójny warunek (GS + alt), ręczna korekta |
| Google OAuth konfiguracja (SHA certs, Play Console) | 🟡 średni | Osobny task setupu; testować wcześnie |
| Brak internetu podczas eksportu | 🟡 średni | Offline queue w SQLite; sync gdy sieć wróci |
| Dokładność elewacji lotniska (baza danych) | 🟡 średni | Rejestracja elewacji po kliknięciu START (GPS alt w momencie off-block) |

### Wymagania systemowe

- Android 10+ (API 29+)
- Uprawnienia: `ACCESS_FINE_LOCATION`, `FOREGROUND_SERVICE`, `INTERNET`
- Działa w tle (GPS tracking gdy ekran wygaszony)
- Offline-first: wszystkie dane lokalne w SQLite, sync opcjonalny

### AGENT 4 — Algorytm detekcji startów i lądowań

```
Jesteś ekspertem od algorytmów i React Native. Implementujesz rdzeń aplikacji lotniczej.

ZADANIE: Zaimplementuj hook useFlightDetection() wykrywający starty i lądowania na podstawie GPS.

ZNANE PROBLEMY do rozwiązania:
- ciasne zakręty mogą powodować chwilowy spadek GS do zera → fałszywe lądowanie
- słaby sygnał GPS może powodować skoki wysokości → fałszywy start
- consumer GPS ma dokładność ~5m, elewacja może skakać o ±20ft

ALGORYTM:

Stałe (konfigurowalny plik src/constants/gps.ts):
  TAKEOFF_SPEED_KT = 50        // próg prędkości GS do detekcji startu
  LANDING_SPEED_KT = 35        // próg prędkości do detekcji lądowania
  TAKEOFF_ALT_DIFF_FT = 50     // różnica wysokości względem alt lotniska
  LANDING_ALT_DIFF_FT = 30     // powrót poniżej tej wysokości = lądowanie
  TAKEOFF_CONFIRM_SEC = 3      // ile sekund warunek musi być spełniony
  LANDING_CONFIRM_SEC = 5      // ile sekund (dłużej bo zakręty)
  COOLDOWN_AFTER_TAKEOFF_SEC = 60   // ignoruj przez 60s po starcie
  COOLDOWN_AFTER_LANDING_SEC = 30   // ignoruj przez 30s po lądowaniu

Logika:
  1. Przy ENGINE START → zapisz altitude_ft jako airport_elevation
  2. Co sekundę sprawdzaj:
     
     DETEKCJA STARTU (gdy inFlight === false):
       conditionMet = (speed_kt > TAKEOFF_SPEED_KT) || (altitude_ft - airport_elevation > TAKEOFF_ALT_DIFF_FT)
       jeśli conditionMet przez TAKEOFF_CONFIRM_SEC sekund → zapisz takeoff, inFlight = true, start cooldown
     
     DETEKCJA LĄDOWANIA (gdy inFlight === true):
       conditionMet = (speed_kt < LANDING_SPEED_KT) && (altitude_ft - airport_elevation < LANDING_ALT_DIFF_FT)
       jeśli conditionMet przez LANDING_CONFIRM_SEC sekund → zapisz landing, inFlight = false, start cooldown
     
     W trakcie cooldown → ignoruj wszelkie detekcje

  3. Przy każdej detekcji → zapisz do SQLite (flight_legs), emituj event do store

INTERFACE hooka:
  useFlightDetection(engineSessionId: number) => {
    inFlight: boolean,
    takeoffCount: number,
    landingCount: number,
    manualTakeoff: () => void,
    manualLanding: () => void,
    detectionLog: DetectionEvent[]   // do debugowania
  }

DODATKOWE:
- zapis DetectionEvent do AsyncStorage jako debug log (ostatnie 100 eventów)
- opcja wyłączenia auto-detekcji w ustawieniach (tylko tryb ręczny)
- unit testy dla algorytmu (Jest) z przypadkami brzegowymi:
  - ciasny zakręt (GS=0 przez 2s, ale alt wysoka)
  - turbulencje (alt skacze ±30ft)
  - poprawny start i lądowanie
```
